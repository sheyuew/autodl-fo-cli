# Operating AutoDL

For AutoDL login, account selection, instances, images, stock, create/clone, data-disk expansion, automatic GPU acquisition, AutoPanel files, or task results, read [docs/codex.md](docs/codex.md) first. Use `bash ./fo` subcommands with `--json`; login and foreground watch commands use a terminal instead. `bash ./fo --help` is the current command reference. Default execution is local and requires no server or invitation.

1. Check `doctor --json` and select the user's account. Resolve ambiguous instance names, paths, or destinations before submitting a change.
2. On `LOGIN_REQUIRED` or a closed local session, ask the user to run `bash ./fo login` in their own local terminal and return when done. For AutoPanel authentication, provide `bash ./fo panel login HANDLE`. Passwords stay in hidden terminal prompts; never request them in chat or pass secrets through arguments, environment variables, JSON, files, or Git.
3. Read and preview freely within the request. For a manual mutation, show the actual object, parameters, full quote, and consequences; obtain the user's final `yes/no` before execute. A changed plan or quote requires fresh confirmation. Never generate the user's answer.
4. For automatic acquisition, obtain final `yes/no` for the policy: mode, target/source, regions, GPU/count, image, driver if constrained, extra paid data-disk capacity, full hourly price cap, polling interval, maximum attempts/time, and one successful acquisition only. This consent allows the engine to re-quote and submit within those exact bounds. State that the monitoring deadline does not turn off an acquired instance. Change the policy only through a new preview and confirmation. Extra data-disk GB excludes the host's free capacity; use zero for no paid expansion. System-disk expansion is outside this version.
5. Inspect returned state or task results before reporting completion. An accepted request is not a finished transfer or a running instance. Acquisition is complete only when the provider reports the exact returned instance UUID as running. After an uncertain submission, query state before considering a retry. Restarted tasks retain records but need a new confirmed policy to acquire again.

Sessions are isolated per account and kept only in local process memory. Use the selected account consistently across preview, execution, and follow-up. Active acquisition tasks keep the local helper alive and continue after the login terminal closes; the computer must stay awake and online. Logout stops local tasks. Accepted AutoPanel cloud transfers continue independently. Keep legacy `remote` configuration separate from the default local workflow.
